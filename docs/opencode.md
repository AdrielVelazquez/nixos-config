# OpenCode configuration

OpenCode is the only coding harness installed by either active host:
`homeConfigurations.cachyos-framework13` and the Home Manager user in
`nixosConfigurations.razer14`.

The pinned upstream [Home Manager OpenCode module](https://nix-community.github.io/home-manager/options/home-manager/programs/opencode.html)
provides the declarative interface:

- `programs.opencode.package` selects the official OpenCode v2 flake package.
- `programs.opencode.settings` generates the OpenCode configuration.
- `programs.opencode.skills` installs complete skill directories, including their
  supporting scripts and references. Compound Engineering uses its locked flake
  source. OpenSpec uses templates generated by the packaged upstream CLI during
  a Nix build, with only OpenCode selected. Neither needs an activation installer.
- OpenSpec commands use Home Manager file declarations because the upstream
  commands option treats generated store-path strings as command text.

## MCP servers

Home Manager also provides [`programs.mcp.servers`](https://nix-community.github.io/home-manager/options/home-manager/programs/mcp.html)
and `programs.opencode.enableMcpIntegration`. Its current OpenCode adapter emits
the v1 `mcp.<name>` schema. This repository follows v2, which expects
`mcp.servers.<name>`, so servers are declared directly through
`programs.opencode.settings.mcp.servers` and automatic integration stays disabled.
Local server executables can use Nix package paths; remote servers need no local
installation.

[Serena supplies an official Nix flake](https://github.com/oraios/serena/blob/main/docs/02-usage/020_running.md).
It is absent from this repository's pinned Nixpkgs. The existing Headroom
integration still registers Serena through `uvx`; that installation has not been
migrated. Using Serena's upstream flake is a supported Nix route, but its command
must also be preserved by Headroom's per-session MCP registration.

The existing SOPS GitHub token retains its legacy `codex_github_token` key.
The launcher reads its decrypted file only at runtime; the generated config
contains an environment reference, never the credential value.

## Plugins and remaining limitations

[OpenCode v2 plugins](https://opencode.ai/v2/docs/build/plugins) are configured with
`programs.opencode.settings.plugins`. Local plugins can reference Nix store paths,
as the Headroom adapter already does. The private LLM Platform plugin retains
its versioned npm URL and is fetched by OpenCode at runtime. Home Manager can
declare that reference, but does not package arbitrary npm plugins and their
dependencies into the Nix store. Fully offline installation would require a
separate Nix derivation for that plugin.

The Headroom wrapper and v2 adapter remain necessary for session-specific proxy
configuration; they are runtime integration, not skill/plugin installers.
Their upstream removal criteria remain in `TODO.md`.

Applying the configurations removes packages and files previously managed by
Home Manager. It does not erase personal agent histories, credentials, manually
installed files, or rollback generations.
